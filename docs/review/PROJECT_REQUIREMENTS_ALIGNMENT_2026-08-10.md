# 斗罗人生模拟器：产品需求与年度主循环对齐稿

状态：`living alignment / Day 15 已确认部分已进入 production`

日期：2026-08-10

用途：记录项目负责人已经确认的产品方向、核心玩法语义和内容边界。本文是审阅材料，不是 Day 15 任务书，不自动授权代码或 Git 操作。

## 一、首要产品目标

项目的首要产品是：

> 尽快形成从开局到神界、内容丰富但允许部分条目较浅的完整人生模拟。

开发优先级以玩家可感知的完整人生进展为中心，不以持续扩建基础设施或把少量内容打磨成孤立高完成度切片为中心。

每个 `Day N` 应完成一个玩家可以明显感受到的新能力或内容阶段，产生实质性项目推进；“只增加一个年龄或一个转盘”本身不构成充分的阶段目标。

## 二、现有原型的定位

- V1 与 V2 都是引擎和功能测试开发形成的雏形，不是必须长期并列维护的两套正式游戏。
- V1 可以继续充当旧事件系统和回归测试样本。
- V2 可以继续提供 Player、年度事务、转盘流程和派生战力等技术能力。
- 正式产品不应被“V1 默认入口”或“V2 当前只有 6 岁 playtest”的历史状态永久限制。
- 历史上的三个武魂 6 岁觉醒内容只保留为技术 fixture；Day 15 的 V2 production 路径已改为读取 271 项正式目录并执行完整觉醒链。

## 三、内容来源与审定规则

`0.1初版汇总.xlsx` 及其无损 JSON 转换结果只作为借鉴和候选内容库。

规则如下：

1. 每个候选内容进入正式游戏前都需要负责人确认。
2. 旧表中的名称、目录位置、权重和推断流程不自动成为 production 真相。
3. 可以批量提出分类、品质、属性和内容等级建议，但建议不得冒充确认结果。
4. 审定通过可筛选的批量工作簿进行；本阶段已完成 349 项保留定义审定，其中 271 项进入主模式目录。
5. 重复名称应合并为唯一武魂定义；原目录信息保留为来源证据或标签提示。

## 四、内容模式

技术字段继续区分：

| canonLevel | 含义 | 主模式 |
| --- | --- | --- |
| `canon` | 官方作品中明确存在的内容 | 允许 |
| `expanded` | 符合斗罗世界观的原创或合理扩展 | 允许 |
| `crossover` | 明显来自其他作品或跨界体系 | 不允许 |
| `parody` | 恶搞、夸张娱乐内容 | 不允许 |

主模式允许：

```json
["canon", "expanded"]
```

后期可以建立独立娱乐模式，再选择性开放 `crossover` 和 `parody`。

## 五、开局语义

### 角色年龄与世界时期分离

- `Player.age` 从 `0` 开始，角色从出生经历完整人生。
- 旧表中的“穿越时期/起始时间点”表示角色出生时所处的斗罗历史时期，不表示 Player 以高年龄直接开局。
- 正式字段建议使用 `worldEra` 或同义字段，避免与 `Player.age` 混淆。

### 开局生成候选维度

开局生成至少需要逐步审定以下内容：

```text
世界时期
→ 性别
→ 种族
→ 出生地
→ 颜值或外貌等级
→ 进入 0 岁年度人生
```

先天魂力和武魂不在 0 岁预生成。它们在 6 岁武魂觉醒主活动中才抽取并原子提交，避免 0～5 岁提前持有尚未觉醒的武魂状态。

## 六、年度主循环

正式年度顺序为：

```text
基于当前 Player.age 创建年度会话
→ 执行年龄主活动
→ 推进并存的跨年剧情路线
→ 执行每年必备的普通修炼
→ 抽取 0～2 次特殊日常活动
→ 年度全部成功后原子结算
→ 年龄增加 1
```

约束：

- 日常活动不能发生在年龄主活动之前。
- 跨年剧情路线与年龄主活动、普通修炼、特殊日常活动并存，不自动替代它们。
- “没有特殊日常事件”是合法结果，但不取消本年必备的普通修炼。
- 特殊日常活动次数本身由转盘决定。
- 年度中任一步骤失败时，不得留下部分 Player、history、spin 或路线状态。

### 已确认的年龄主活动锚点

| 年龄 | 主活动 |
| ---: | --- |
| 6 | 先天魂力与完整武魂觉醒 |
| 7 | 初级学院抽取 |
| 12 | 高级学院抽取 |
| 18 | 成人势力选择抽取 |

其他年龄的主活动、修炼池和路线内容继续按阶段审定，不根据 WheelID 顺序自动补全。

## 七、6 岁先天魂力

先天魂力与天赋等级是同一套结果的数值和等级表达。

| 先天魂力 | 天赋等级 | 已确认语义 |
| ---: | --- | --- |
| 0 | F | `Player.level = 0`；仍可觉醒武魂，但魂力等级永久锁死，无法通过普通修炼提升 |
| 1 | E | `Player.level = 1` |
| 2 | D | `Player.level = 2` |
| 3 | D | `Player.level = 3` |
| 4 | C | `Player.level = 4` |
| 5 | C | `Player.level = 5` |
| 6 | B | `Player.level = 6` |
| 7 | B | `Player.level = 7` |
| 8 | A | `Player.level = 8` |
| 9 | A | `Player.level = 9` |
| 10 | S | `Player.level = 10` |
| 20 | 神级天赋 | `Player.level = 20`；“神级”只描述天赋等级，不是武魂品质 |

先天魂力影响：

- 武魂数量的抽取概率；
- 武魂品质的抽取概率；
- 特殊天赋的出现率和数量；
- 觉醒后的初始等级和派生战力；
- 后续每年普通修炼可以进入的成长池。

先天魂力不影响武魂基础形态。

低天赋仍有极小概率获得多武魂、顶级或极致武魂；不使用“未达到等级便绝对不可能”的硬品质门槛。

## 八、正式武魂模型

旧表的九个武魂目录混合了不同维度，不能继续作为九个互斥类别。

正式模型至少分开：

```text
唯一武魂定义
├─ 基础形态：器 / 兽 / 植物 / 本体 / 食物 / 其他
├─ 固有品质：低等 / 普通 / 顶级 / 极致
├─ 属性：允许第一版暂缺，后续补充
├─ 性质标签：邪灵、变异、divine 等
└─ canonLevel：canon / expanded / crossover / parody
```

“神级武魂”不再作为品质或互斥基础类别：

- 原目录条目重新归入真实基础形态；
- 品质最高仍为“极致”；
- 确有神性性质时使用 `divine` 标签；
- “神级天赋”仍可作为先天魂力 20 级的天赋标签存在。

一个武魂进入第一版可玩池的最低资料为：

1. 唯一名称；
2. 唯一定义 ID；
3. 基础形态；
4. 固有品质；
5. `canonLevel`；
6. 属性允许暂缺，后续补充。

## 九、武魂品质战斗力系数

以下数值是武魂品质对等级战力的加成系数，绝不是武魂品质的抽取概率：

| 品质 | 战斗力系数 |
| --- | ---: |
| 低等 | 0% |
| 普通 | 10% |
| 顶级 | 25% |
| 极致 | 30% |

抽取概率由独立概率表按先天魂力决定；品质战斗力由玩家实际抽中的武魂定义决定。两者必须在文档、数据字段和 UI 中分开命名。

## 十、完整武魂觉醒顺序

6 岁主活动的目标流程为：

```text
抽取先天魂力 / 天赋等级
→ 根据先天魂力抽取武魂数量 1～4
→ 按先天魂力抽取一次共享品质，并应用到全部武魂槽位
→ 为每个槽位独立抽取基础形态（不受先天魂力影响）
→ 从“已审定 + 形态匹配 + 品质匹配 + 主模式允许”的定义池抽取具体武魂
→ 排除已拥有的重复定义
→ 创建对应武魂实例
→ 写入初始等级、spin 和年度 history
→ 年度成功后原子提交
→ Player.age 从 6 推进至 7
```

完整流程确实需要的重复、分派和去重能力属于由正式内容直接证明的运行需求，不属于脱离内容的基础设施膨胀。
