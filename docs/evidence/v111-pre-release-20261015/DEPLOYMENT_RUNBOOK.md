## 提交及 PR

1. 只使用 candidate-paths.txt 的显式文件白名单；按 candidate-files.json 复核 SHA-256。禁止整体 add，不纳入 owner 的 V10_ASCENSION_CLOSURE 历史差异或其他未跟踪材料。
2. 重新读取远端 main/tag、候选 HEAD 和暂存区。当前 HEAD 与 main 提交不同但树相同；若发生远端更新，先审查冲突及新增范围，再重新验证。
3. 获得选择性提交/推送/创建 PR 授权后执行，使用 PR_DRAFT.md。CI 完成后记录准确 head SHA；云端缺 vault 时两项来源条件测试可明确跳过，不冒充本地源检查。
4. 合并 main 会触发原有 Pages。提交/PR 授权不包含合并、部署、tag 或 Release；这些需另行明确授权。

## 部署后验收

先备份测试槽和需要保留的线上存档。保存部署提交及 HTML 原文字节，对照静态包 manifest；检查主页、兼容 v10.html、JS/JSON/CSS 带版本的实际响应字节及 SHA/SRI。

使用升级前已打开的 V1.1.0 页：先手动导出未保存人生，验证旧页继续运行；普通刷新及重新打开后验证 /8 开局/读档、四路线、未自动恢复与原槽保护。核对 CDN 带查询参数的缓存命中/失效，不能仅凭200或部署成功认定通过。

Android 真机复验新增中文特质、转盘动画、抽屉、键盘/旋转、后台恢复和 JSON 选择/取消；有 iOS 再独立记录。已有 Android15 回报仅对应 V1.1.0，不能代替本候选。不要为线上验收重新从零运行目标九考；可从合法既有 /8 测试快照检查读档和后继操作。

入口或子模块失败须停止启动且不写槽；数据失败保留原文备份。线上不主动制造破坏性 CDN 故障，失败注入留在隔离环境。
