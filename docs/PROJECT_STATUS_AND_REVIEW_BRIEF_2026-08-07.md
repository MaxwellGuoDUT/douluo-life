## 四、Codex 浏览器点击能力的优先级判断

### 判断

完善 Codex 对浏览器的点击、DOM 读取和控制台检查能力，不是当前最紧要的产品开发任务，但属于应该近期补齐的 P1 验收基础设施。

它不应阻塞以下 P0 工作：

- 统一年龄推进语义；
- 整理项目当前真相源；
- 处理已暂存材料的提交边界；
- 设计第一条正式 V2 内容切片。

它对以下工作具有较高价值：

- 验证 V1 主入口没有回归；
- 对 `v2-demo.html` 连续点击推进多个年度；
- 检查年龄、spin、history、战力和 warning 的 DOM 输出；
- 检查浏览器控制台错误；
- 后续进行 UI 调整和真实交互回归。

OpenAI 官方 Codex 用例页将“构建并在实时浏览器中测试网页游戏”列为支持的工作流：  
<https://developers.openai.com/codex/use-cases>

但“Codex 支持这种工作流”不等于“当前任务已经具备完整点击能力”。本地是否可用，必须以一次实际的页面导航、点击、DOM 读取和控制台检查为准。

### 建议执行边界

将浏览器能力配置安排为一个独立、限时的工具任务：

1. 设定 30 至 60 分钟的排查上限；
2. 验证插件是否安装并启用；
3. 验证当前任务是否真正挂载浏览器控制能力；
4. 使用 `v2-demo.html` 完成一次端到端点击测试；
5. 若仍不可用，记录明确失败层级，停止扩展排查，不阻塞项目主线。

除非下一阶段立即进行大量 UI 开发，否则不建议把浏览器配置升级为 P0。

## 八、正式内容迁移状态

`data/v2/examples/` 当前主要用于验证结构和运行时，不等于正式游戏内容库。

`data/reference/legacy-wheel/` 保存旧表转换结果和推断材料，共整理出 510 个旧转盘，但具有以下边界：

- 原表没有完整跳转图；
- WheelID 相邻不能自动解释为剧情跳转；
- `orderedWheelIds` 只是候选顺序；
- `nextWheelId` 和 effects 大量缺失；
- `inferred` 不能自动升级为 `confirmed`；
- 标题中的“你选择”是随机结果叙事，不代表玩家手动选择按钮。

当前不适合进行 510 个转盘的全量自动迁移。
