# 天赋系统 v1.0（Day16 独立实现）

状态：规则目录和运行时已建立；特殊池、机会池、遭遇池、魂核成长池仍为空并标记 `unresolved`。

规则配置：`data/config/talent.json`

规则目录：`data/rules/talent.json`

纯函数实现：`js/talent-system.js`

## 1. 独立边界

天赋等级不作为战力系数，也不修改既有战力目录、战力配置、战力计算器、Player v2 或年度流程。

运行时接收独立 JSON 配置和输入，返回独立 JSON 结果；随机抽取使用调用方注入的 RNG，便于确定性测试。

负数是真实退步。对负向结果，当前大等级最低值为：

```js
Math.floor((currentLevel - 1) / 10) * 10 + 1
```

因此 `21 - 5 = 21`、`31 - 5 = 31`；`20` 和 `30` 仍分别属于 `11–20`、`21–30`，全局最低等级为1。正向结果按 `currentLevel + delta` 计算，可以突破到下一个大等级。

乡下平民会移除当前成长池中的负向条目，再对剩余条目等概率抽取。

## 4. 出生身份

身份在出生阶段抽取，默认所有当前可选条目等权且互斥。重生者只有第二人生及以后可选。

每个身份条目同时保留 `talent.docx` 的叙述文本；出生事件会先展示该文本，再让身份立即生效。武魂觉醒事件则展示生产目录返回的武魂名称、形态、品质和属性。

## 5. 独立池和未决状态

以下池保持独立字段，不并入普通成长池：

- `specialTalents`
- `opportunity`
- `encounterGrowth`
- `soulCoreGrowth`

本版本前三个池以及91级后的魂核池均为空。调用这些池时返回结构化 `unresolved` 结果，不伪造条目、权重或概率。

宗门子女的同名替换要求普通池中存在同名条目；如果找不到，运行时返回 `MISSING_SAME_NAME_ORDINARY_RESULT`，不自行改名或生成内容。

重生实体通过 `regenerateEntities` 深拷贝并生成新 `instanceId`，保留实体名称和数据内容，但不复用上一世对象引用。

## 6. 运行时接口

```js
validateTalentConfig(config)
validateTalentRules(catalog)
mapInnateSoulPowerToTalentGrade(innateSoulPower, config)
drawBirthIdentity({ config, rng, lifeNumber })
resolveBirthState({ config, baseInnateSoulPower, identityId, lifeNumber })
resolveAnnualGrowth({ config, currentLevel, talentGrade, identityId, rng })
drawSpecialTalent({ config, identityId, rng })
drawOpportunityPool({ config, identityId, additionalDraws, rng })
inheritReincarnatedState(previousLife)
```

所有函数均不访问 DOM、不写回 Player、不修改传入配置；配置状态和未决边界由规则目录保留。
